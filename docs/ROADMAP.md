# After 0.2 — priorities for 0.3

0.2 delivers the Paper & Graphite UI, independent Mixer/selection Inspector, actual recorded starter pack, basic SFZ multisampling, note/browser audition, metronome, loops, SMF import and simple EQ/Delay/Reverb. 0.1 playback/recording/project/export paths remain. The next release should deepen reliability and musical control before expanding catalog quantity.

1. **Recording and devices:** real microphones, permission allow/deny, long sessions/hotplug/disk-full, input monitoring, latency compensation, device/sample-rate/buffer settings, clock drift and external MIDI keyboard device selection/recording. External hardware MIDI input is not implemented in 0.2.
2. **Real-time quality:** profile worst-case graph changes, transport/master/clip-edge smoothing, effect reset cost on seek/loop, held-note phase recovery, sample loop crossfades and higher-quality resampling. Add a central bounded/LRU sample pool and history memory policy; extend long-session stress fixtures.
3. **SoundFont backend:** optional dynamically linked FluidSynth SF2/SF3 with Bank/Program selection, checked dependencies, off-thread load/free, identical live/offline sound and allocation/lock instrumentation of its actual render/note APIs. Do not infer safety from its product description. Include licensed minimal test fixtures before declaring support. No SoundFont backend is present in 0.2.
4. **Sampler and editing:** denser genuine pitch/velocity layers (including guitar and electric keys), round-robin/release triggers/pedal, per-region envelope/filter, authenticated/versioned pack catalogs, optional download/install progress and safe archive ingestion. Current installer deliberately accepts only unpacked verified folders. Add loop handle dragging/count-in, MIDI automation/program/controllers, audio split/left-trim/fades and more precise multi-note property controls.
5. **Mixer:** better reverb topology/damping, parametric EQ, tempo-synced delay time/feedback UI, full effect reorder/bypass and VST3/CLAP extension boundary. Keep all visible effect controls functional.
6. **Release engineering:** signed/notarized self-contained macOS packages, exact corresponding Qt/transitive sources and notices, LGPL replacement/re-sign instructions, Intel/universal and clean-account QA. Then Windows/Linux device/path/atomic-save validation and CI. The current app is a tested development build, not a universal or notarized release.

The original First Light v1 example remains a compatibility fixture. Add migration fixtures for every schema change and retain measured test/screenshot evidence rather than treating a design mockup as a feature.
